La memoria es un arreglo de bytes con dirección

En la Unidad 4 una memoria se describió como un conjunto de celdas, cada una identificada por una dirección que llega por el bus de direcciones. La memoria de un programa en C es exactamente eso: un arreglo gigantesco de bytes numerados desde 0.

Toda variable vive en alguna de esas celdas. El nombre x es una comodidad del compilador; lo que la máquina maneja es la dirección donde x está guardada. Un puntero es, simplemente, una variable que guarda una dirección.

Variable ordinaria

Contiene un valor: int x = 202; guarda el número 202.

Puntero

Contiene una dirección: int *p = &x; guarda dónde vive x.

Los punteros son la razón por la que C puede hacer cosas que otros lenguajes no: devolver varios resultados, recorrer arreglos sin copiarlos, pedir memoria durante la ejecución y escribir directamente en un registro de hardware mapeado a una dirección fija.

Los operadores & y *

Dos operadores bastan para todo el tema, y son inversos uno del otro:

OperadorSe leeQué hace
&xdirección deEntrega la dirección donde está x. Es el mismo & que ya usaba scanf.
*pcontenido deEntrega el valor guardado en la dirección p. Se llama desreferenciar.
/* punteros.c -- lo minimo indispensable */
#include <stdio.h>

int main(void)
{
    int x = 202;
    int *p;             /* p es un puntero a int */

    p = &x;             /* p guarda la direccion de x */

    printf("x        = %d\n", x);
    printf("&x       = %p\n", (void *) &x);     /* la direccion */
    printf("p        = %p\n", (void *) p);      /* la misma     */
    printf("*p       = %d\n", *p);              /* el valor: 202 */

    *p = 7;             /* escribe en x A TRAVES del puntero */
    printf("ahora x  = %d\n", x);               /* 7 */

    return 0;
}

El asterisco aparece en dos papeles distintos, y confundirlos es normal al principio: en int *p; forma parte de la declaración («p es un puntero a int»); en *p = 7; es el operador que accede al contenido.

Un puntero tiene tipo: int *, char *, double *. El tipo no cambia la dirección, pero sí cómo se interpretan los bytes que hay allí y cuánto avanza la aritmética de punteros. void * es un puntero genérico, sin tipo asociado.

El puntero nulo

La constante NULL (definida en stdio.h y otros encabezados) representa «este puntero no apunta a nada». Es el valor que devuelven las funciones cuando fallan, y el que conviene dar a un puntero que todavía no tiene destino.

int *p = NULL;

if (p != NULL) {
    printf("%d\n", *p);    /* solo se desreferencia si es valido */
}

Desreferenciar un puntero nulo termina el programa con una violación de segmento. Eso es, paradójicamente, lo bueno: el error se ve de inmediato. Desreferenciar un puntero sin inicializar es peor, porque contiene una dirección cualquiera y el programa puede seguir corriendo con memoria corrompida.

Regla práctica: todo puntero debe tener un valor desde el momento en que se declara —una dirección válida o NULL—, y debe comprobarse antes de desreferenciarlo cuando pudo haber fallado.

Punteros como salida: el sumador completo, por fin

En la clase 5 el sumador completo tuvo que empaquetar sus dos salidas en un solo entero, porque una función devuelve un único valor. Con punteros el problema desaparece: la función recibe dónde escribir cada salida.

/* sumador_ptr.c -- sumador completo con dos salidas reales */
#include <stdio.h>

void sumador_completo(int a, int b, int cin, int *s, int *cout)
{
    *s    = a ^ b ^ cin;
    *cout = (a & b) | (cin & (a ^ b));
}

int main(void)
{
    int s, cout;

    printf(" A B Cin | S Cout\n");
    printf("---------+-------\n");

    for (int a = 0; a <= 1; a++) {
        for (int b = 0; b <= 1; b++) {
            for (int cin = 0; cin <= 1; cin++) {
                sumador_completo(a, b, cin, &s, &cout);
                printf(" %d %d  %d  | %d   %d\n", a, b, cin, s, cout);
            }
        }
    }

    return 0;
}

La firma de la función ahora se lee como la hoja de datos de un bloque lógico: tres entradas por valor, dos salidas por dirección. Es el patrón estándar en C para una función con varios resultados, y el que usan casi todas las bibliotecas de sistema.

Punteros y arreglos

Aquí se explica la frase que quedó pendiente en la clase anterior. En C, el nombre de un arreglo usado en una expresión se convierte en la dirección de su primer elemento. De ahí que estas dos notaciones sean equivalentes:

int a[4] = {10, 20, 30, 40};

a        /* equivale a  &a[0]        */
a[i]     /* equivale a  *(a + i)     */
&a[i]    /* equivale a   a + i       */

Y de ahí también que pasar un arreglo a una función no copie nada: lo que viaja son 8 bytes con una dirección. Por eso la función sí puede modificar el arreglo del llamador, y por eso sizeof ya no da el tamaño del bloque.

Un arreglo NO es un puntero

int a[4]; reserva 16 bytes de datos. El nombre a no es una variable que se pueda reasignar: a = p; es un error de compilación.

Pero se comporta como uno

En casi toda expresión, y siempre al pasarlo a una función, a se degrada a &a[0]. Dentro de la función, el parámetro int a[] es un int *.

La aritmética de punteros respeta el tipo: sumar 1 a un int * avanza 4 bytes, no 1, porque avanza un elemento. Esto permite recorrer un arreglo sin índices:

int a[4] = {10, 20, 30, 40};

for (int *p = a; p < a + 4; p++) {
    printf("%d ", *p);        /* 10 20 30 40 */
}

Ambas formas son correctas y producen el mismo código máquina. La notación con índices (a[i]) suele ser más legible; la de punteros aparece mucho en código de bibliotecas y conviene saber leerla.

Cadenas vistas como punteros

Una cadena literal es un arreglo de caracteres en memoria, y char *s = \"hola\"; guarda la dirección de su primer carácter. Esto explica una distinción que confunde a menudo:

char s[] = "hola";

Reserva 5 bytes propios y copia el texto allí. El contenido se puede modificar: s[0] = 'H'; es válido.

char *s = "hola";

Guarda la dirección del literal, que está en memoria de solo lectura. s[0] = 'H'; compila pero falla en ejecución.

Por eso los literales se declaran como const char * cuando no se van a modificar. Recorrer una cadena con un puntero es el idioma clásico de C:

int longitud(const char *s)
{
    const char *inicio = s;

    while (*s != '\0') {      /* avanza hasta el terminador */
        s++;
    }

    return s - inicio;        /* la resta de punteros da la distancia */
}

Dónde vive la memoria: estática, pila y montículo

Un programa en ejecución reparte su memoria en tres zonas con comportamientos muy distintos:

ZonaQué guardaCuánto viveTamañoQuién la administra
EstáticaVariables globales y staticTodo el programaFija al compilarEl compilador
Pila (stack)Variables locales y parámetrosMientras dura la llamadaLimitada (unos pocos MB)Automática: se libera al salir
Montículo (heap)Lo pedido con mallocHasta que usted la libereGrande, limitada por el sistemaUsted, con free

La pila explica dos errores ya mencionados: por qué una variable local contiene basura (es memoria reutilizada de llamadas anteriores) y por qué devolver la dirección de una variable local es un error (el espacio se reutiliza en cuanto la función retorna). También explica el desbordamiento de pila de una recursión sin caso base.

El montículo es la única zona cuyo tamaño puede decidirse durante la ejecución, y por eso es la que se usa cuando no se sabe de antemano cuántos datos habrá.

malloc, calloc y free

malloc recibe un número de bytes y devuelve la dirección del bloque reservado, o NULL si no hay memoria. Están declaradas en <stdlib.h>.

#include <stdlib.h>

int *v = malloc(n * sizeof(int));     /* n enteros, sin inicializar */
if (v == NULL) {                      /* SIEMPRE verificar          */
    printf("sin memoria\n");
    return 1;
}

v[0] = 5;                             /* se usa como un arreglo normal */

free(v);                              /* devolver la memoria */
v = NULL;                             /* evitar el puntero colgante */
FunciónQué haceDetalle
malloc(n)Reserva n bytes sin inicializarContiene basura hasta que usted escriba
calloc(n, tam)Reserva n elementos de tam bytesLos pone todos en cero
realloc(p, n)Cambia el tamaño de un bloquePuede moverlo: use siempre el puntero devuelto
free(p)Devuelve el bloque al sistemaDespués de esto, p ya no es válido

Escribir sizeof(int) en lugar de 4 no es pedantería: es lo que hace que el programa siga siendo correcto en otra máquina o con otro tipo. La forma más robusta de escribirlo evita incluso nombrar el tipo:

int *v = malloc(n * sizeof *v);       /* "n veces el tamano de lo que v apunta" */

Por cada malloc debe existir exactamente un free. Ni cero (fuga de memoria) ni dos (corrupción del montículo). En programas largos conviene decidir desde el diseño quién es responsable de liberar cada bloque.

Ejemplo: tabla de verdad de N variables

Un programa que genera la tabla de verdad de una función de n variables no puede declarar el arreglo de antemano: necesita 2ⁿ filas y n se conoce hasta la ejecución. Este es el caso que justifica la memoria dinámica.

/* tabla_dinamica.c -- tabla de verdad de n variables (n leido en ejecucion) */
#include <stdio.h>
#include <stdlib.h>

int main(void)
{
    int n;

    printf("Numero de variables (1 a 10): ");
    if (scanf("%d", &n) != 1 || n < 1 || n > 10) {
        printf("valor invalido\n");
        return 1;
    }

    int filas = 1 << n;                        /* 2^n */

    int *tabla = malloc(filas * sizeof *tabla);
    if (tabla == NULL) {
        printf("sin memoria para %d filas\n", filas);
        return 1;
    }

    /* F = (x0 AND x1) OR (NOT x2)  usando los bits del indice */
    for (int i = 0; i < filas; i++) {
        int x0 = (i >> (n - 1)) & 1;
        int x1 = (n >= 2) ? (i >> (n - 2)) & 1 : 0;
        int x2 = (n >= 3) ? (i >> (n - 3)) & 1 : 0;

        tabla[i] = (x0 & x1) | (!x2);
    }

    printf("\nindice | entradas | F\n");
    printf("-------+----------+---\n");
    for (int i = 0; i < filas; i++) {
        printf("  %3d  | ", i);
        for (int b = n - 1; b >= 0; b--) {
            printf("%d", (i >> b) & 1);
        }
        printf("     | %d\n", tabla[i]);
    }

    int unos = 0;
    for (int i = 0; i < filas; i++) {
        unos += tabla[i];
    }
    printf("\nF vale 1 en %d de %d combinaciones\n", unos, filas);

    free(tabla);                               /* devolver la memoria */
    tabla = NULL;

    return 0;
}

El índice de la fila es el valor binario de las entradas: el bit b del índice da el valor de la variable correspondiente. Ese truco —recorrer i de 0 a 2ⁿ−1 y extraer sus bits— genera cualquier tabla de verdad sin escribir bucles anidados.

Los cuatro errores de memoria

ErrorQué se hizoConsecuencia
Fuga de memoriaSe pide con malloc y nunca se liberaEl programa crece hasta agotar la memoria. No falla de inmediato, lo que lo hace difícil de notar.
Puntero colganteSe usa un puntero después de freeLa memoria ya pertenece a otro. Se leen o escriben datos ajenos.
Doble liberaciónfree(p) dos veces sobre el mismo bloqueCorrompe las estructuras internas del montículo; el programa falla más adelante, lejos del error.
Puntero sin inicializarint *p; *p = 5;Escribe en una dirección arbitraria. Es el error más destructivo porque puede no fallar nunca.

Ninguno de los cuatro produce un error de compilación. Por eso en C se usan herramientas que vigilan la memoria en ejecución:

$ gcc -std=c11 -Wall -Wextra -g -fsanitize=address programa.c -o programa
$ ./programa
    # aborta en la linea exacta del acceso invalido

$ valgrind --leak-check=full ./programa
    # reporta cada bloque no liberado y donde se habia pedido

Acostúmbrese a compilar con -fsanitize=address mientras desarrolla y a quitarlo solo en la versión final. Encuentra en segundos errores que de otro modo cuestan horas.

Cierre: del programa al hardware

Esta unidad empezó con un printf que imprimía una tabla de verdad escrita a mano y termina con un programa que genera la de cualquier función de n variables en memoria pedida durante la ejecución. En el camino, cada estructura del lenguaje tuvo un equivalente en lo que ya se había construido con compuertas:

En CEn el curso
Operadores & | ^ ~Compuertas AND, OR, XOR, NOT (Unidad 2)
if / switchMultiplexores y decodificadores (Unidad 3)
Bucles anidadosRecorrido exhaustivo de una tabla de verdad (Unidad 2)
FuncionesBloques lógicos reutilizables: medio sumador, sumador completo (Unidad 3)
Variables staticElementos con estado: latches y flip-flops (Unidad 4)
ArreglosRegistros, registros de desplazamiento y memorias (Unidad 4)
PunterosDirecciones y bus de direcciones

La continuación natural es la Unidad 7: un FPGA se describe con HDL, pero las herramientas que lo sintetizan, el software que carga el bitstream y el firmware que acompaña al sistema están escritos en C. Saber ambos lados es lo que permite diseñar un sistema digital completo.

Ejercicios propuestos

  1. Escriba una función void intercambia(int *a, int *b) que intercambie dos enteros, y compruebe desde main que los valores realmente cambiaron.
  2. Escriba una función void divide(int n, int divisor, int *cociente, int *residuo) que devuelva ambos resultados por puntero.
  3. Escriba una función void separa_nibbles(int byte, int *alto, int *bajo) que separe un byte en sus dos mitades de 4 bits.
  4. Modifique el sumador de 4 bits de la clase 5 para que use la versión con punteros de sumador_completo y devuelva el resultado y el acarreo de salida por separado.
  5. Escriba un programa que pida n, reserve con malloc un arreglo de n enteros, lo llene con los valores leídos del teclado, calcule el promedio y libere la memoria.
  6. Escriba una función int *gray_tabla(int bits) que reserve y devuelva un arreglo con la secuencia completa de código Gray de bits bits. El llamador es responsable de liberarla.
  7. Modifique tabla_dinamica.c para que la función booleana se lea como una lista de mintérminos desde el teclado, en lugar de estar escrita en el código.
  8. Escriba una función void invierte(char *s) que invierta una cadena usando dos punteros que avanzan desde los extremos hacia el centro.
  9. Compile un programa con una fuga de memoria deliberada y ejecútelo bajo valgrind. Interprete el reporte y luego corrija la fuga.
  10. Escriba un programa que simule una memoria de 16 posiciones de 8 bits reservada dinámicamente, con operaciones de lectura y escritura por dirección, y un menú que las ofrezca en un bucle.
