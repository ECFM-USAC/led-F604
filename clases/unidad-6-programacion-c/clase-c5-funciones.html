Una función es un bloque lógico

En la Unidad 3 ningún circuito se dibujó compuerta por compuerta de principio a fin. Se construyó un medio sumador, luego un sumador completo a partir de dos medios sumadores, y luego un sumador de 4 bits conectando cuatro sumadores completos. Cada bloque se diseñó una vez, se verificó una vez y se reutilizó.

Una función es exactamente eso en software: un trozo de código con un nombre, unas entradas (los parámetros) y una salida (el valor de retorno). Quien la usa solo necesita saber qué hace, no cómo lo hace.

Bloque lógico

Entradas, salida, una tabla de verdad que lo describe y una caja que oculta las compuertas internas.

Función en C

Parámetros, valor de retorno, un nombre que describe lo que hace y un cuerpo que oculta la implementación.

Dividir un programa en funciones no es una formalidad: hace el código comprobable por partes, elimina la repetición y permite cambiar una implementación sin tocar a quien la llama. printf es una función escrita por otra persona y usada sin conocer su interior.

Definir y llamar una función

Una definición de función tiene cuatro partes: el tipo de lo que devuelve, el nombre, la lista de parámetros con sus tipos, y el cuerpo entre llaves.

int cuadrado(int x)      /* tipo | nombre | parametros */
{
    return x * x;        /* cuerpo: devuelve un valor  */
}

La llamada aparece dentro de una expresión. El control salta a la función, se ejecuta su cuerpo y, al llegar a return, vuelve al punto de llamada con un valor:

/* cuadrado.c -- definicion y uso de una funcion */
#include <stdio.h>

int cuadrado(int x)
{
    return x * x;
}

int main(void)
{
    int n = 7;
    int r = cuadrado(n);          /* llamada: r recibe 49 */

    printf("%d al cuadrado es %d\n", n, r);
    printf("y 3 al cuadrado es %d\n", cuadrado(3));

    return 0;
}

return termina la función de inmediato, aunque queden líneas por debajo. Una función puede tener varios return, uno por cada camino de salida.

Prototipos: declarar antes de usar

El compilador lee el archivo de arriba abajo. Si encuentra una llamada a una función que todavía no conoce, no puede verificar ni el número ni el tipo de los argumentos. Por eso una función debe declararse antes de usarse, aunque se defina después.

Esa declaración adelantada se llama prototipo: es el encabezado de la función seguido de punto y coma.

#include <stdio.h>

int cuadrado(int x);          /* PROTOTIPO: solo la firma */

int main(void)
{
    printf("%d\n", cuadrado(5));   /* el compilador ya sabe que existe */
    return 0;
}

int cuadrado(int x)           /* DEFINICION: el cuerpo */
{
    return x * x;
}

Poner los prototipos arriba y main primero permite leer el programa de lo general a lo particular. Es la organización que se usará en adelante.

Si se omite el prototipo, los compiladores antiguos suponían que la función devolvía int. C11 ya no lo permite y gcc -Wall avisa: implicit declaration of function. Esa advertencia significa casi siempre que falta un #include o un prototipo.

Paso por valor

En C los argumentos se pasan por valor: la función recibe una copia. Modificar el parámetro dentro de la función no afecta a la variable del llamador.

/* por_valor.c -- la funcion recibe una copia */
#include <stdio.h>

void intenta_cambiar(int x)
{
    x = 100;                            /* modifica la copia local */
    printf("dentro:  x = %d\n", x);     /* 100 */
}

int main(void)
{
    int n = 5;

    intenta_cambiar(n);
    printf("afuera:  n = %d\n", n);     /* 5, no 100 */

    return 0;
}

Esto es una ventaja: una función no puede alterar por accidente las variables de quien la llama. Pero también impone un límite —una función devuelve un solo valor— que se nota en cuanto se quiere modelar un bloque con dos salidas, como un sumador completo con S y Cout.

Solución de hoy

Empaquetar las dos salidas en un solo entero, un bit cada una, tal como viajarían por un bus de dos líneas.

Solución de la clase 7

Pasar la dirección de las variables de salida con punteros, para que la función escriba directamente en ellas.

Funciones sin retorno y sin parámetros

Cuando una función no devuelve nada —porque su trabajo es imprimir, configurar o modificar un estado— su tipo de retorno es void. Cuando no recibe nada, su lista de parámetros es void.

#include <stdio.h>

void encabezado(void)
{
    printf(" A | B | S | Cout\n");
    printf("---+---+---+-----\n");
}

int main(void)
{
    encabezado();          /* la llamada es una sentencia completa */
    return 0;
}

Escribir int main() con los paréntesis vacíos no es lo mismo que int main(void): lo primero significa «lista de parámetros no especificada» y desactiva una verificación del compilador. Use siempre void cuando no haya parámetros.

Ámbito de las variables

El lugar donde se declara una variable determina quién puede verla y cuánto vive.

ClaseDónde se declaraQuién la veCuánto vive
Local (automática)Dentro de una función o bloqueSolo ese bloqueNace al entrar y muere al salir. Su valor inicial es basura si no se inicializa.
ParámetroEn la lista de la funciónSolo esa funciónEs una variable local inicializada con la copia del argumento.
Global (externa)Fuera de toda funciónTodo el archivoVive durante todo el programa y se inicializa en cero. Úselas con moderación.
static localDentro de una función, con staticSolo esa funciónConserva su valor entre llamadas, como un registro que recuerda el estado anterior.

Una variable static local es el equivalente en software de un flip-flop dentro de un bloque: la función «recuerda» sin que nadie afuera pueda tocar ese estado.

int contador(void)
{
    static int n = 0;     /* se inicializa UNA sola vez */
    n++;
    return n;
}
/* llamadas sucesivas devuelven 1, 2, 3, ... */

Las variables globales parecen cómodas porque evitan pasar parámetros, pero cualquier función puede modificarlas y eso hace imposible razonar sobre el programa por partes. Prefiera siempre parámetros y valores de retorno.

Ejemplo: las compuertas como funciones

El primer paso para construir circuitos en software es dar nombre a las compuertas básicas. Cada una es una función de una línea:

/* compuertas.c -- las compuertas basicas como funciones */
#include <stdio.h>

int and_g(int a, int b)  { return a & b; }
int or_g (int a, int b)  { return a | b; }
int xor_g(int a, int b)  { return a ^ b; }
int not_g(int a)         { return !a;    }

int main(void)
{
    printf(" A | B | AND | OR | XOR | NOT A\n");
    printf("---+---+-----+----+-----+------\n");

    for (int a = 0; a <= 1; a++) {
        for (int b = 0; b <= 1; b++) {
            printf(" %d | %d |  %d  | %d  |  %d  |   %d\n",
                   a, b, and_g(a, b), or_g(a, b), xor_g(a, b), not_g(a));
        }
    }

    return 0;
}

El programa no es más corto que usar &, | y ^ directamente, pero ahora existe un vocabulario: a partir de aquí se construyen bloques mayores llamando a estas funciones, igual que se dibuja un circuito a partir de símbolos de compuerta.

Ejemplo: medio sumador y sumador completo

El medio sumador tiene dos salidas: la suma (A ⊕ B) y el acarreo (A · B). Como una función devuelve un solo valor, se empaquetan los dos bits en un entero: el bit 0 es la suma y el bit 1 el acarreo.

/* sumador.c -- medio sumador, sumador completo y sumador de 4 bits */
#include <stdio.h>

/* devuelve (Cout << 1) | S */
int medio_sumador(int a, int b)
{
    int s    = a ^ b;
    int cout = a & b;
    return (cout << 1) | s;
}

/* sumador completo construido con DOS medios sumadores y un OR,
   igual que el circuito de la Unidad 3                          */
int sumador_completo(int a, int b, int cin)
{
    int h1 = medio_sumador(a, b);
    int h2 = medio_sumador(h1 & 1, cin);      /* suma de h1 con Cin */

    int s    = h2 & 1;
    int cout = ((h1 >> 1) & 1) | ((h2 >> 1) & 1);

    return (cout << 1) | s;
}

int main(void)
{
    printf(" A B Cin | S Cout\n");
    printf("---------+-------\n");

    for (int a = 0; a <= 1; a++) {
        for (int b = 0; b <= 1; b++) {
            for (int cin = 0; cin <= 1; cin++) {
                int r = sumador_completo(a, b, cin);
                printf(" %d %d  %d  | %d   %d\n",
                       a, b, cin, r & 1, (r >> 1) & 1);
            }
        }
    }

    return 0;
}

La salida reproduce, línea por línea, la tabla de verdad del sumador completo del libro. Y la función sumador_completo no usa las fórmulas booleanas finales: compone dos llamadas a medio_sumador, exactamente como el circuito compone dos bloques.

Ejemplo: sumador de 4 bits con acarreo en cascada

Con el sumador completo ya disponible, el sumador de 4 bits es un bucle que lo llama cuatro veces, pasando el acarreo de salida de una etapa como acarreo de entrada de la siguiente. Es literalmente el ripple carry adder.

/* suma4.c -- sumador de 4 bits por acarreo en cascada */
#include <stdio.h>

int sumador_completo(int a, int b, int cin);   /* definido en el ejemplo anterior */

int suma4(int a, int b)
{
    int resultado = 0;
    int carry = 0;

    for (int i = 0; i < 4; i++) {
        int ai = (a >> i) & 1;
        int bi = (b >> i) & 1;

        int r = sumador_completo(ai, bi, carry);

        resultado |= (r & 1) << i;      /* coloca el bit S en su posicion */
        carry = (r >> 1) & 1;           /* el acarreo pasa a la etapa siguiente */
    }

    return (carry << 4) | resultado;    /* bit 4 = acarreo de salida */
}

int main(void)
{
    int a = 9, b = 7;                   /* 1001 + 0111 */
    int r = suma4(a, b);

    printf("%2d + %2d = %2d  (suma de 4 bits = %d, Cout = %d)\n",
           a, b, a + b, r & 0xF, (r >> 4) & 1);
    return 0;
}

9 + 7 = 16 no cabe en cuatro bits: el programa imprime suma 0 y Cout = 1, que es justo lo que haría el circuito. Probar casos de desbordamiento es la mejor forma de verificar que la implementación corresponde al hardware.

Recursión

Una función puede llamarse a sí misma. Para que eso termine hacen falta dos cosas: un caso base que no se llama a sí mismo, y que cada llamada se acerque a ese caso.

La conversión a binario por divisiones sucesivas quedó pendiente en la clase anterior porque producía los bits al revés. Con recursión el orden se resuelve solo: primero se imprime el resto del número, y al final el último bit.

/* binario_rec.c -- imprime un numero en binario, recursivamente */
#include <stdio.h>

void imprime_binario(int n)
{
    if (n > 1) {                       /* caso recursivo */
        imprime_binario(n / 2);
    }
    putchar('0' + (n % 2));            /* caso base incluido */
}

int main(void)
{
    int n = 202;
    printf("%d en binario es ", n);
    imprime_binario(n);
    putchar('\n');
    return 0;
}

Para n = 202 la cadena de llamadas baja hasta imprime_binario(1) y, al regresar, cada nivel imprime su bit: 11001010. Las llamadas pendientes se guardan en la pila, una zona de memoria que volverá en la clase 7.

Toda función recursiva puede escribirse con un bucle, y viceversa. La recursión gana cuando el problema es naturalmente recursivo (recorrer un árbol, dividir y vencer); el bucle gana en velocidad y uso de memoria.

Dividir el programa en varios archivos

Cuando el conjunto de funciones crece, se separa en módulos: un archivo .h con los prototipos (la «hoja de datos» del bloque) y un .c con las definiciones (el circuito interno).

/* ---- compuertas.h : la interfaz ---- */
#ifndef COMPUERTAS_H
#define COMPUERTAS_H

int and_g(int a, int b);
int or_g (int a, int b);
int xor_g(int a, int b);
int sumador_completo(int a, int b, int cin);

#endif
/* ---- compuertas.c : la implementacion ---- */
#include "compuertas.h"

int and_g(int a, int b) { return a & b; }
int or_g (int a, int b) { return a | b; }
int xor_g(int a, int b) { return a ^ b; }

int sumador_completo(int a, int b, int cin)
{
    int s    = xor_g(xor_g(a, b), cin);
    int cout = or_g(and_g(a, b), and_g(cin, xor_g(a, b)));
    return (cout << 1) | s;
}
/* ---- main.c : el programa ---- */
#include <stdio.h>
#include "compuertas.h"

int main(void)
{
    int r = sumador_completo(1, 1, 1);
    printf("S = %d, Cout = %d\n", r & 1, (r >> 1) & 1);
    return 0;
}

La compilación une los dos archivos objeto en un solo ejecutable:

$ gcc -std=c11 -Wall -Wextra -c compuertas.c    # -> compuertas.o
$ gcc -std=c11 -Wall -Wextra -c main.c          # -> main.o
$ gcc compuertas.o main.o -o programa           # enlaza

Las líneas #ifndef / #define / #endif son un guardia de inclusión: evitan que el contenido del encabezado se inserte dos veces si varios archivos lo incluyen. Los comillas en #include "compuertas.h" indican un archivo propio; los ángulos, uno del sistema.

Ejercicios propuestos

  1. Escriba las funciones nand_g, nor_g y xnor_g a partir de las ya definidas, y agregue sus columnas a la tabla de verdad de compuertas.c.
  2. Escriba una función int nand3(int a, int b, int c) usando solo llamadas a nand_g. Verifique con una tabla de verdad que es correcta. (Es el ejercicio de compuertas universales de la Unidad 2, resuelto en software.)
  3. Escriba una función int paridad(int n) que devuelva el bit de paridad par de un byte, y úsela en un programa que la calcule para los valores de 0 a 255.
  4. Escriba una función int cuenta_bits(int n) y una función int gray(int n). Imprima una tabla de 0 a 15 con el valor, su código Gray y cuántos bits en 1 tiene cada uno.
  5. Escriba una función int resta4(int a, int b) que reste dos números de 4 bits usando suma4 y complemento a dos (invertir b y sumar 1). Compruebe varios casos, incluyendo resultados negativos.
  6. Escriba una función recursiva int potencia(int base, int exp) y otra iterativa equivalente. Compare el resultado de ambas para 2¹⁰.
  7. Escriba una función recursiva que imprima un número en cualquier base de 2 a 16, usando los dígitos 0-9 y A-F.
  8. Reorganice su solución del ejercicio 5 en tres archivos (aritmetica.h, aritmetica.c, main.c) y compílelos por separado.
