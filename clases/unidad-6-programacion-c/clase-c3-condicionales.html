Del multiplexor al if

Hasta ahora los programas se ejecutaban línea por línea, de arriba abajo, sin alternativas. Una estructura condicional permite que el programa elija qué camino seguir según el valor de una expresión. Es el equivalente en software de algo que ya se construyó en hardware: un multiplexor selecciona una de varias entradas según las líneas de selección; un if selecciona uno de varios bloques de código según una condición.

En hardware (Unidad 3)

Un MUX 2→1 entrega D0 o D1 según S. Las dos entradas existen siempre; la selección solo decide cuál se propaga a la salida.

En software

Un if/else ejecuta uno de dos bloques según la condición. El bloque no elegido no se ejecuta: no consume tiempo ni produce efectos.

Esa es la diferencia conceptual que conviene tener clara: el circuito evalúa todo en paralelo y descarta; el programa decide y evalúa solo lo necesario.

La sentencia if

La forma más simple ejecuta un bloque solo si la condición es verdadera, es decir, si la expresión entre paréntesis vale cualquier cosa distinta de cero:

if (expresion) {
    /* se ejecuta si expresion != 0 */
}

Un ejemplo con contenido del curso: determinar si un número es par mirando su bit menos significativo, que es justo lo que haría un circuito con una sola línea.

/* paridad.c -- par o impar segun el bit 0 */
#include <stdio.h>

int main(void)
{
    int n;

    printf("Ingrese un entero: ");
    scanf("%d", &n);

    if ((n & 1) == 0) {
        printf("%d es par  (bit 0 = 0)\n", n);
    }

    return 0;
}

n & 1 aísla el bit menos significativo, igual que n % 2 pero sin división. Es la forma habitual de probar paridad en firmware.

if ... else

Para cubrir también el caso contrario se agrega else. Se ejecuta exactamente uno de los dos bloques, nunca los dos ni ninguno.

if ((n & 1) == 0) {
    printf("%d es par\n", n);
} else {
    printf("%d es impar\n", n);
}

Las llaves son opcionales cuando el bloque tiene una sola sentencia, pero omitirlas es una fuente conocida de errores:

Peligroso

if (n > 0)
    printf("positivo\n");
    printf("siempre se imprime\n");

La indentación sugiere que ambas líneas dependen del if. No es así: solo la primera. El compilador no mira los espacios.

Recomendado

if (n > 0) {
    printf("positivo\n");
    printf("tambien condicional\n");
}

Con llaves siempre, el bloque es explícito y agregar una línea después no cambia el significado del programa.

En este curso se usan llaves incluso para una sola sentencia. Cuesta dos caracteres y evita el error más común al modificar código ajeno.

Cadenas else if: el comparador de magnitud

Cuando hay más de dos alternativas se encadenan: cada else lleva otro if. Las condiciones se evalúan en orden y se ejecuta solo la primera que resulte verdadera; el else final atrapa todo lo que no encajó.

if (condicion1) {
    /* ... */
} else if (condicion2) {
    /* ... */
} else if (condicion3) {
    /* ... */
} else {
    /* ninguna de las anteriores */
}

El comparador de magnitud de la Unidad 3 —el circuito con salidas A>B, A=B y A<B— se escribe así:

/* comparador.c -- comparador de magnitud de dos numeros de 2 bits */
#include <stdio.h>

int main(void)
{
    int a, b;

    printf("Ingrese A (0-3): ");
    scanf("%d", &a);
    printf("Ingrese B (0-3): ");
    scanf("%d", &b);

    if (a > b) {
        printf("A > B   ->  salidas: 1 0 0\n");
    } else if (a == b) {
        printf("A = B   ->  salidas: 0 1 0\n");
    } else {
        printf("A < B   ->  salidas: 0 0 1\n");
    }

    return 0;
}

Nótese que las tres salidas son mutuamente excluyentes, igual que en el circuito: la estructura else if garantiza esa exclusividad sin escribir ninguna condición adicional.

La sentencia switch

Cuando la decisión depende de el valor de un entero y no de una comparación, switch es más claro que una cadena de else if. Compara la expresión contra una lista de valores constantes:

switch (expresion_entera) {
    case valor1:
        /* ... */
        break;
    case valor2:
        /* ... */
        break;
    default:
        /* si ninguno coincide */
        break;
}

Tres reglas, y las tres importan:

  • Los case deben ser constantes enteras (o caracteres). No se puede escribir case n > 5: ni usar double.
  • El break termina el switch. Si se omite, la ejecución continúa en el siguiente case; eso se llama fall-through y casi siempre es un error.
  • default es opcional pero recomendable: cubre el caso no previsto, igual que las entradas «no importa» de un mapa de Karnaugh deben decidirse explícitamente.

El fall-through es útil cuando varios valores comparten la misma acción: case 2: case 3: case 5: printf("primo\n"); break; agrupa tres casos deliberadamente, sin código repetido.

Ejemplo: un multiplexor 4→1 en software

El MUX 4→1 toma cuatro entradas de datos y dos líneas de selección. En software, las líneas de selección forman un número de 2 bits y cada case es una de las cuatro entradas.

/* mux4.c -- multiplexor 4 a 1 */
#include <stdio.h>

int main(void)
{
    int d0 = 1, d1 = 0, d2 = 1, d3 = 1;   /* entradas de datos */
    int s1, s0, sel, y;

    printf("Entradas: D0=%d D1=%d D2=%d D3=%d\n", d0, d1, d2, d3);
    printf("Seleccion S1 S0 (0 o 1 cada una): ");
    scanf("%d %d", &s1, &s0);

    sel = (s1 << 1) | s0;        /* dos bits -> un numero de 0 a 3 */

    switch (sel) {
        case 0:  y = d0;  break;
        case 1:  y = d1;  break;
        case 2:  y = d2;  break;
        case 3:  y = d3;  break;
        default:
            printf("seleccion invalida\n");
            return 1;
    }

    printf("S1 S0 = %d%d  ->  Y = D%d = %d\n", s1, s0, sel, y);
    return 0;
}

La línea sel = (s1 << 1) | s0; es la misma idea de la clase anterior: dos bits sueltos se arman en un solo número con un desplazamiento y un OR. A partir de ahí, el switch reproduce exactamente la tabla de selección del multiplexor.

Ejemplo: selector de operación de una ALU

Una unidad aritmético-lógica recibe dos operandos y un código de operación. El código de operación es, en software, el valor sobre el que decide el switch.

/* alu.c -- ALU de 4 operaciones sobre dos valores de 4 bits */
#include <stdio.h>

int main(void)
{
    int a, b, op, y;

    printf("A (0-15): ");   scanf("%d", &a);
    printf("B (0-15): ");   scanf("%d", &b);
    printf("Operacion  0=SUMA  1=RESTA  2=AND  3=OR : ");
    scanf("%d", &op);

    switch (op) {
        case 0:  y = a + b;  printf("SUMA  : ");  break;
        case 1:  y = a - b;  printf("RESTA : ");  break;
        case 2:  y = a & b;  printf("AND   : ");  break;
        case 3:  y = a | b;  printf("OR    : ");  break;
        default:
            printf("codigo de operacion invalido\n");
            return 1;
    }

    printf("%d (0x%X)\n", y, y & 0xF);
    return 0;
}

y & 0xF recorta el resultado a cuatro bits, que es lo que haría una ALU de 4 bits al descartar el acarreo de salida. Sin esa máscara, 12 + 9 daría 21 en lugar de 5 con acarreo.

El operador condicional ?:

C tiene un operador que elige entre dos valores (no entre dos bloques). Se escribe condicion ? valor_si_verdadero : valor_si_falso y es el único operador de C con tres operandos.

int mayor = (a > b) ? a : b;        /* el maximo de a y b */

int y = s ? d1 : d0;                /* un MUX 2->1 en una linea */

printf("%d es %s\n", n, (n & 1) ? "impar" : "par");

Es compacto y, usado con mesura, legible: la segunda línea es la definición misma de un multiplexor 2→1. Anidado varias veces se vuelve ilegible; en ese caso use if/else.

Errores clásicos con condicionales

ErrorSe ve asíQué ocurre realmente
= en lugar de ==if (x = 0)Asigna en vez de comparar. La condición vale lo asignado, así que if (x = 5) es siempre verdadero. -Wall lo reporta.
Punto y coma de másif (n > 0);El ; es el cuerpo completo del if: el bloque que sigue se ejecuta siempre. No produce error de compilación.
Comparar flotantes con ==if (x == 0.1)Casi nunca se cumple. Use if (fabs(x - 0.1) < 1e-9) con math.h.
Confundir & con &&if (a & b)2 & 1 vale 0 (falso) aunque ambos sean distintos de cero. Para condiciones use &&; para bits, &.
Encadenar comparacionesif (0 < x < 10)Se evalúa (0 < x), que da 0 o 1, y luego < 10: siempre verdadero. Escriba if (0 < x && x < 10).
break olvidadocase 1: y = a;La ejecución cae al siguiente case. Revise cada case antes de dar por terminado un switch.

Ejercicios propuestos

  1. Modifique paridad.c para que además indique si el número es cero, positivo o negativo, usando una cadena else if.
  2. Escriba un programa que lea tres bits A, B y C y evalúe la función F = A·B + C' usando únicamente if y operadores lógicos. Compruebe las ocho combinaciones a mano.
  3. Escriba un decodificador BCD a 7 segmentos: lea un dígito de 0 a 9 y muestre qué segmentos (a a g) se encienden, usando switch. Para dígitos fuera de rango, apague todos los segmentos.
  4. Amplíe mux4.c a un multiplexor 8→1 con tres líneas de selección. Verifique que sel = (s2 << 2) | (s1 << 1) | s0 recorre los ocho casos.
  5. Escriba un sumador completo de un bit: lea A, B y Cin, y calcule S y Cout con if. Compare su resultado con la expresión booleana S = A ⊕ B ⊕ Cin implementada con ^.
  6. Agregue a alu.c las operaciones XOR, NOT A, desplazamiento a la izquierda y desplazamiento a la derecha. Indique además si el resultado desbordó los 4 bits.
  7. Escriba un programa que lea una calificación de 0 a 100 e imprima la letra correspondiente (A, B, C, D, F). Hágalo dos veces: con else if y con switch sobre nota / 10. Comente cuál resulta más claro.
